# 2. Architecture

## 2.1 Stack

| Concern | Choice | Why |
|---------|--------|-----|
| Language | TypeScript (strict) | shared rule model between UI, compiler and engines |
| Build / cross-browser | **WXT** (Vite-based) | per-browser manifest generation (`chrome`, `safari` targets), file-based entrypoints, `browser.*` namespace shim, HMR for the options page |
| UI | **Preact** + Tailwind CSS | small bundle (matters for Safari/iOS), familiar Tailwind workflow |
| State | signals (`@preact/signals`) + a thin store over `browser.storage` | no heavy state library |
| Validation / schema | **Zod** | one schema for rule JSON, import/export and migrations |
| Regex safety | `re2js` for pre-validation in the UI, `declarativeNetRequest.isRegexSupported()` at compile time | DNR uses RE2 syntax; catch unsupported constructs before saving |
| Tests | Vitest (unit), Playwright (Chrome e2e with `--load-extension`), XCTest + Safari WebDriver (`safaridriver`) for Safari smoke | |
| Lint/format | ESLint (typescript-eslint), Prettier | |
| Package manager | pnpm | |
| Safari wrapper | Xcode project generated by `xcrun safari-web-extension-converter`, committed to the repo | |

Flow when the user saves a rule set:

1. Options page validates with Zod and writes `RuleSet` to `storage.local`
   (key `ruleset.v1`).
2. Background listens on `storage.onChanged`, runs `compile(ruleSet, capabilities)`.
3. Compiler returns `{ dnrRules, fallbackRules, report }`.
   `report` lists every condition that could not be compiled to DNR and why.
4. Background replaces all dynamic DNR rules atomically
   (`updateDynamicRules({removeRuleIds: previousIds, addRules})`).
5. Background (re)configures the fallback engine with `fallbackRules`
   and (un)registers the MAIN-world content script only if at least one
   fallback rule needs it.
6. Report is stored under `compile.report.v1` so the UI can show badges.

## 2.4 Rule model (packages/core/src/model)

```ts
type RuleSet = { schemaVersion: 1; rules: Rule[]; settings: Settings };

type Rule = {
  id: string;              // uuid
  name: string;
  enabled: boolean;
  priority: number;        // 1..n, higher wins; UI exposes drag ordering
  condition: ConditionNode;
  action: Action;
  scope?: { resourceTypes?: ResourceType[] };   // quick filter, ANDed with condition
  notes?: string;
  createdAt: string; updatedAt: string;
};

type ConditionNode =
  | { type: "group"; op: "and" | "or"; not?: boolean; children: ConditionNode[] }
  | { type: "cond"; not?: boolean; field: Field; operator: Operator; value: string | string[] };

type Field =
  | "url" | "scheme" | "host" | "port" | "path" | "query" | "queryParam"  // queryParam: value = [name, expected]
  | "fragment" | "method" | "resourceType" | "initiatorDomain" | "domainType"
  | "requestHeader" | "requestBody" | "requestBodyField"                 // fallback-only
  | "responseHeader" | "responseStatus";                                   // Chrome DNR / fallback

type Operator = "equals" | "notEquals" | "contains" | "startsWith" | "endsWith"
  | "matchesRegex" | "matchesWildcard" | "in" | "exists" | "notExists"
  | "gt" | "lt";   // numeric: port, status

type Action =
  | { type: "redirect"; mode: "url"; url: string }
  | { type: "redirect"; mode: "regexSubstitution"; pattern: string; substitution: string }
  | { type: "redirect"; mode: "transform"; transform: URLTransform }
  | { type: "block" }
  | { type: "allow" }
  | { type: "modifyHeaders"; request?: HeaderOp[]; response?: HeaderOp[] };
```

Design notes:

- The tree is normalised to **disjunctive normal form (DNF)** before
  compilation: `(A AND B) OR (C AND NOT D)`. Each disjunct becomes one DNR
  rule (same action, same priority). This is the core trick that makes an
  arbitrary AND/OR designer fit DNR's "one flat condition per rule" model.
- A hard limit of **64 disjuncts per rule** after DNF expansion protects
  the 5,000-rule budget; the designer warns at 16 and refuses above 64
  ("simplify this rule or split it").
- `NOT` on a leaf compiles to the `excluded*` DNR fields when one exists
  (`excludedRequestMethods`, `excludedRequestDomains`, `excludedResourceTypes`,
  `excludedInitiatorDomains`); otherwise it forces the fallback engine or a
  negative-lookahead-free regex rewrite (RE2 has no lookahead, so most
  negated URL conditions go to fallback and are flagged).

## 2.5 Compiler: condition tree → DNR (packages/core/src/compile)

Per disjunct (a conjunction of leaves):

| Leaf field + operator | DNR mapping |
|-----------------------|-------------|
| `host equals/endsWith` | `requestDomains` |
| `host notEquals` | `excludedRequestDomains` |
| `method in` | `requestMethods` (Safari 26+ / Chrome 91+) |
| `resourceType in` | `resourceTypes` |
| `initiatorDomain in` | `initiatorDomains` |
| `domainType` | `domainType` |
| `responseHeader` (Chrome) | `responseHeaders` / `excludedResponseHeaders` |
| `url/scheme/port/path/query/queryParam/fragment` with `contains/startsWith/endsWith/equals/matchesWildcard` | merged into **one** `urlFilter` when exactly one URL-ish leaf exists, otherwise merged into one anchored `regexFilter` |
| any `matchesRegex` | `regexFilter` (all URL-ish leaves of the disjunct are folded into one RE2 regex using lookahead-free concatenation; if folding is impossible the disjunct is marked `fallback`) |
| `requestHeader*`, `requestBody*`, `responseHeader` on Safari | **not compilable** → disjunct goes to the fallback engine |

Output rule shape:

```ts
{ id, priority: basePriority(rule) , action: mapAction(rule.action),
  condition: { ...merged, isUrlFilterCaseSensitive: false } }
```

- Rule ids: deterministic `hash(ruleId, disjunctIndex) % 2^31`, stored in a
  map so re-compiles replace rather than duplicate.
- **Priority**: user order ×10, leaving room for the engine to insert
  anti-loop `allow` rules at priority+1 for the redirect target when the
  target matches the same condition (detected at compile time by evaluating
  the condition against the target URL with the in-JS evaluator).
- Validate every regex with `isRegexSupported` before applying; on failure
  the report records `regexUnsupported` and the UI shows the error inline.
- Budget check: if compiled rules exceed `min(5000, browserMax)` the apply
  is rejected with a clear message, never silently truncated.
- The compiler is pure and has a **golden-file test suite**: designer JSON in,
  DNR JSON out, per browser target.

## 2.6 Fallback engine (packages/extension/lib/fallback)

For conditions DNR cannot express. Two tiers, both clearly labelled in the UI.

### Tier A — Navigation observe-and-redirect (documents only)

- Uses non-blocking `webRequest.onBeforeSendHeaders` (request headers),
  `onBeforeRequest` (`requestBody`, POST form data) and `onHeadersReceived`
  (response headers/status, Safari only since Chrome does it in DNR).
- Evaluates the full condition tree with the in-JS evaluator from `core`.
- If a match is found for a `main_frame`/`sub_frame` request:
  `tabs.update(tabId, {url: target})` (main frame) or
  `scripting.executeScript` → `location.replace(target)` (sub frame).
- Honest limitations, shown in the UI: the original request has already
  started (server sees it once), only navigations can be redirected this
  way, and `requestBody` is only available for POST/PUT with form or raw
  bodies. Safari listeners must be synchronous.

### Tier B — In-page fetch/XHR interception (XHR, fetch, beacons)

- `scripting.registerContentScripts({world: "MAIN", runAt: "document_start",
  persistAcrossSessions: true})` only for the hosts the user has granted and
  only while at least one fallback rule exists.
- Wraps `window.fetch`, `XMLHttpRequest.prototype.open/setRequestHeader/send`
  and `navigator.sendBeacon`. Evaluates conditions against method, URL,
  headers and body; on match performs the action in-page: rewrite the URL
  before sending (redirect), throw/return a 0-byte response (block), or
  add/remove headers.
- Rule data reaches the MAIN world via the isolated-world `bridge.ts`
  (`postMessage` with a per-page nonce), never via inline script.
- Limitations shown in the UI: cannot touch requests the page did not start
  from JS (images, CSS, scripts, navigations), cannot read `HttpOnly`/forbidden
  headers, CSP may block injection on some sites.

### Capability detection

`lib/capabilities.ts` returns a `Capabilities` object at startup by probing
(`'requestMethods' in …` style checks are impossible for DNR, so use
`browser.runtime.getBrowserInfo` on Safari where available, UA sniffing
fallback, plus a one-time `updateSessionRules` probe with a `requestMethods`
rule to confirm support). The compiler takes `Capabilities` as input; the UI
reads it to draw badges.

## 2.7 Permissions and manifest (generated per target by WXT)

```jsonc
{
  "manifest_version": 3,
  "permissions": [
    "declarativeNetRequest",
    "declarativeNetRequestWithHostAccess",   // needed for redirect in Safari and Chrome
    "declarativeNetRequestFeedback",         // match log (dev builds only on Chrome)
    "storage", "scripting", "tabs", "webRequest", "activeTab"
  ],
  "optional_host_permissions": ["<all_urls>"],
  "background": { "service_worker": "background.js" },   // WXT emits `scripts` for safari target if needed
  "action": { "default_popup": "popup.html" },
  "options_ui": { "page": "options.html", "open_in_tab": true },
  "browser_specific_settings": { "safari": { "strict_min_version": "26.0" } }
}
```

Host access is requested per rule: when a rule is saved the extension
computes the host patterns it needs and calls `permissions.request`. The
popup shows a "this site is not allowed yet" state with a one-click grant,
matching Safari's per-site model and keeping Chrome Web Store review simple.

## 2.8 Storage and data

- `storage.local`: `ruleset.v1` (rules), `settings.v1`, `compile.report.v1`.
- `storage.session`: `matchlog` ring buffer (last 200 matches: rule id,
  URL, engine, timestamp) for the popup "recent activity" view.
- Import/export: JSON file (`application/json`, schema-versioned). Also a
  share-string (base64url of gzip JSON) for pasting one rule.
- No remote code, no telemetry, no network calls from the extension itself.
  `storage.sync` is intentionally not used (Safari does not sync it).

## 2.9 Migration and versioning

`core/src/migrate` holds `v0 → v1 …` functions; background runs them on
`runtime.onInstalled` (`reason: "update"`). Every exported file carries
`schemaVersion`.
