# 3. UI and UX

## 3.1 Surfaces

| Surface | Purpose |
|---------|---------|
| Options page (opens in a tab) | Rule list, logic designer, rule tester, import/export, settings, match log |
| Popup | Global on/off, per-site permission grant, rules active on the current tab, recent matches, open designer |
| Badge | matches on the current tab (`setExtensionActionOptions({displayActionCountAsBadgeText})` on both; Safari ignores badge colour) |
| Blocked page | extension page shown by Tier A when a navigation is blocked: rule name, URL, "allow once" |

## 3.2 Rule list

- Table: enabled toggle, name, auto-generated condition summary (grammar in
  §3.7), action summary, fidelity badge (`Exact` / `Best effort` /
  `Unsupported here`), drag handle plus up/down buttons for ordering (touch).
- Bulk actions: enable/disable, duplicate, delete, export selected.
- Search filtering by name, host, action target.
- Budget meter in the footer: "DNR rules used: 37 / 5,000 (Chrome)" or
  "expanded rules: 120 / 30,000 (Safari)".

## 3.3 Logic designer

```
[ Match ALL of ▾ ]                                   (root group: AND / OR, NOT toggle)
 ├─ [host ▾] [ends with ▾] [api.example.com]       🟢 Exact
 ├─ [method ▾] [is one of ▾] [POST ✓ PUT ✓]         🟢 Exact
 └─ [ Match ANY of ▾ ]
     ├─ [request header ▾] [X-Env] [equals ▾] [staging]   🟡 Best effort (page requests + navigations)
     └─ [query param ▾] [env] [equals ▾] [staging]        🟢 Exact
[+ condition] [+ group]
```

Behaviour:

- Field picker groups operands: URL parts; Request (method, headers, body);
  Response (headers, status, disabled on Safari with a tooltip); Context
  (resource type, initiator, first/third party).
- Operators depend on the field (numeric fields get `>`/`<`; header fields
  get `exists`/`not exists`).
- Live fidelity badge per leaf and per rule, computed by running the compiler
  in the page with the current browser's `Capabilities`; hovering shows the
  reason and the tier.
- Regex inputs validate on each keystroke: syntax (`re2js`), then the
  portable subset (§2.6.3). Messages name the construct ("alternation `|` is
  not supported in Safari; split into two conditions with OR").
- Header-name inputs validate against the Safari allowlist when running on
  Safari; a custom name shows "Safari can only set this header for requests
  the page starts (best effort)".
- DNF size indicator: "this rule expands to 6 browser rules" with the warning
  at 16 and the refusal at 64.
- Action editor: redirect target with `\1…\9` capture pickers rendered from
  the regex; transform mode gives per-part fields (scheme, host, port, path,
  query add/replace/remove, fragment); `javascript:`, `data:`, `file:` and
  other-extension targets are rejected inline.
- Loop warning when the target matches the same rule (§2.6.4).
- Keyboard accessible, light/dark via `prefers-color-scheme`, RTL-safe
  (Tailwind logical properties), usable at 390 px width.

## 3.4 Rule tester

Panel on the options page: URL, optional method, headers (key/value rows),
body. Output: the list of rules that match (in precedence order), the winning
action, the resulting URL, and per rule the engine that would act. On
Chrome the DNR layer is additionally checked with
`declarativeNetRequest.testMatchOutcome` and any disagreement with the
evaluator is shown as a bug-report prompt (it should never happen; it is our
own consistency check).

## 3.5 Templates / presets

Shipped as JSON in `public/presets/` and offered from the empty state:
"Production host → localhost:3000", "Force HTTPS for host", "Swap API
environment by query param", "Block tracking pixels on host", "Add
`Authorization` header to my API host", "Strip `utm_*` parameters".

## 3.6 Onboarding and permission UX

- First run opens the options page with a 3-step empty state: create a rule,
  grant site access, see it work.
- When a rule needs a host that is not granted, saving shows "Grant access to
  api.example.com and api-staging.example.com" (both origin and destination
  on Safari). On Safari the user may instead grant from the toolbar badge;
  the UI explains both.
- When a rule cannot work at all on the current browser (response header
  modification on Safari), the save is allowed, the rule is marked
  "Unsupported here" and it is skipped by the compiler, so an exported file
  still works on Chrome.

## 3.7 Condition summary grammar

`host ends with "api.example.com" AND method in [POST, PUT] AND (query env =
"staging" OR header X-Env = "staging")`. Generated from the tree, truncated
at 120 characters with a tooltip for the full text. Same strings are used in
the match log and the blocked page.

## 3.8 Copy and i18n

All strings in `_locales/en/messages.json` from day one; Arabic (`ar`) in
Phase 6; layout is RTL-safe from Phase 3.
