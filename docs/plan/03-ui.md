# 3. UI and UX

## 3.1 Surfaces

| Surface | Purpose |
|---------|---------|
| Options page (opens in a tab) | Rule list, logic designer, import/export, settings, rule tester, match log |
| Popup | Global on/off, per-site permission grant, list of rules active on the current tab, "open designer" |
| Badge | number of matches on the current tab (Chrome: `setExtensionActionOptions({displayActionCountAsBadgeText})`; Safari: manual badge via `action.setBadgeText`) |

## 3.2 Rule list

- Table: enabled toggle, name, short condition summary (auto-generated from
  the tree, e.g. `host ends with "example.com" AND method in [POST, PUT]`),
  action summary, fidelity badge (`DNR` / `Best effort` / `Unsupported here`),
  drag handle for priority.
- Bulk actions: enable/disable, duplicate, delete, export selected.
- Search box filtering by name, host, action target.

## 3.3 Logic designer

A nested group editor, similar to a query builder:

```
[ Match ALL of ▾ ]                                   (root group: AND / OR)
 ├─ [host ▾] [ends with ▾] [example.com]       🟢 DNR
 ├─ [method ▾] [is one of ▾] [POST ✓ PUT ✓]     🟢 DNR
 └─ [ Match ANY of ▾ ]  (nested group)
     ├─ [request header ▾] [X-Env ▾] [equals ▾] [staging]   🟡 Best effort
     └─ [query param ▾] [env] [equals ▾] [staging]          🟢 DNR
[+ condition] [+ group]   [NOT] toggle per row and per group
```

Behaviour:

- Field picker groups operands: URL parts, Request (method, headers, body),
  Response (headers, status; disabled on Safari with a tooltip), Context
  (resource type, initiator, first/third party).
- Operator list depends on the field (numeric fields get `>`/`<`; header
  fields get `exists`/`not exists`).
- Live fidelity badge per leaf and per rule, computed by running the compiler
  in the page with the current browser's `Capabilities`.
- Regex inputs validate with `re2js` on each keystroke and show the RE2
  error; unsupported constructs (lookahead, backreferences) are named.
- A **"Test against URL"** panel: user pastes a URL (optionally method,
  headers, body); the page shows which rules would match and the resulting
  URL, using the in-JS evaluator for the tree and, on Chrome, also
  `declarativeNetRequest.testMatchOutcome` for the DNR layer so the two can
  be compared.
- Action editor: redirect target with `{{capture}}` placeholders rendered
  from the regex; "transform" mode gives per-part fields (scheme, host,
  port, path, query add/replace/remove, fragment).
- Loop detection warning when the target matches the same rule.
- Keyboard accessible, Tailwind styling, light/dark via
  `prefers-color-scheme`, RTL-safe layout (Tailwind logical properties).

## 3.4 Templates / presets

Shipped as JSON in `public/presets/` and offered from an empty state:

- "Force HTTPS for host", "Localhost dev proxy (prod host → localhost:3000)",
  "Swap API environment (query param env=)", "Block tracking pixels on host",
  "Add header `X-Debug: 1` to my API".

## 3.5 Onboarding and permission UX

- First run opens the options page with a 3-step empty state: create a rule,
  grant site access, see it work.
- When a rule needs a host that is not granted, saving shows a "Grant access
  to example.com" button that triggers `permissions.request`. On Safari the
  user may instead grant from the toolbar badge; the UI explains both.

## 3.6 Copy and i18n

- All strings in `_locales/en/messages.json` from day one (Safari and Chrome
  both support `i18n.getMessage`). Arabic (`ar`) added in Phase 6 since the
  owner's audience may need it; layout already RTL-safe.
